# 分析MCP安全接入与连接验收

用于首次连接、换客户端、权限或工具缺失排查。先发现现有连接与配置说明，复用项目客户端或成熟MCP实现，不新写协议栈。以下工具名属于支持质量分析扩展的Traks部署，不能据此假定上游或另一实例具有同样能力。

## 1. 分清六类配置

| 配置 | 作用 | 不可替代的边界 |
| --- | --- | --- |
| 网站collector地址、siteId、埋点版本 | 网站发送事件 | 站点标识不是后台读权限；构建配置与运行时配置分别检查 |
| Traks MCP HTTPS地址、只读PAT | AI查询已采集数据 | 绑定实例/工作区/允许站点；不能授权发信或部署 |
| LLM provider Coding API地址、Key、model ID | 客户端调用模型 | 与Traks鉴权完全不同；MCP并不要求特定模型供应商 |
| CRM只读连接token | Traks读取本站业务聚合 | 每站单独绑定精确HTTPS origin，不复用PAT或发信Key |
| 邮件发送Key与发送域 | 服务端向获许可的地址发送邮件 | 发送权限不必包含domains/webhooks管理权限 |
| Webhook signing secret与入站域 | 验证供应商回执、路由回复 | 不是发送Key；收信配置不自动授予营销或邮箱抓取权限 |

需要模型配置时，记录用户请求的名称和供应商实际model ID；按当前客户端、供应商官方文档及账号能力确认，不猜别名。用户指定的GLM版本只约束该次配置，不成为新站默认值；未验证标记 `requested_model` 与 `actual_model=unverified`，不静默降级。单独获准的最小模型测试不证明MCP可用，工具测试也不证明Coding订阅或模型路由正确。

## 2. 理解与调研门

1. 绑定目标仓库/生产站/分析实例/站点权限/客户端和版本；确认本轮仅查询、配置还是还包括改站。
2. 检查已暴露的MCP工具；无法发现时按宿主的工具搜索/插件规则处理，再考虑授权HTTP客户端。不因工具未注入就重装整个平台。
3. 只查看配置结构和凭据来源是否存在，不输出配置原文、headers或环境值。确认客户端支持的transport与环境变量/凭据引用语法，不编造通用JSON配置。
4. 在本地私有回执记录精确endpoint与允许站点；通用Skill、Git、公开报告不保存用户实例、账号或真实Key。普通连接失败不触发凭据扩权、付费或网络绕过。

## 3. 决策与最小配置变更

写入前说明“修改哪个客户端的哪一个MCP条目、使用何种凭据引用、是否需重载、如何恢复”。当前授权必须涵盖这次secret/config写入；旧站授权不外推。保留其他server和model配置，私有备份权限不宽于原文件。

优先最小只读、限站点凭据；使用客户端支持的环境/系统凭据存储。不得将Key写进URL、公开命令行参数、日志、截图、Git或SOP，不让用户在聊天粘贴密钥。客户端不支持安全引用时先说明限制并选择受权限保护的本地配置，不能把不支持的占位语法宣称为生效。

只读数据连接与LLM配置分步测试，避免把鉴权错误混为一谈。不要创建新付费资源，也不要默认把整份分析数据发往刚配置的第三方模型；按当前数据处理授权，仅提供必要脱敏聚合。

## 4. 分层连接测试

| 门 | 实际验收动作 | 成功不能推导什么 |
| --- | --- | --- |
| 配置加载 | 客户端重连/重载后确认该条连接被加载 | 文件存在不证明客户端已加载 |
| 协议与工具 | 标准MCP客户端完成 `initialize` / `tools/list`，记录实际返回schema | 工具可见不证明站点权限或生产读取成功 |
| 站点鉴权 | 使用本轮授权的准确siteId完成最小只读查询 | 401/403不能换他站ID碰运气；合法空集不证明没有历史业务 |
| 质量汇总 | 按实际schema调用 `get_quality_insights` | 旧stats/Top-N不能替代质量包，空生产样本不支持流失结论 |
| 完整证据 | 需要明细时按同一period/filters调用 `get_quality_evidence` 到nextCursor=null | 仅第一页、仅汇总、完整窗口摘要均不是完整会话生命周期 |
| 业务聚合 | 需要且已接CRM时调用 `get_crm_quality(siteId, from, to)` | 工具存在不证明本站CRM/发信/送达/回复已接通 |

若请求经营口径、入口或注册指标，分别核对实际 `business`、`entryFunnels`、`registrations` 能力；它们是可选fork扩展，不是所有Traks版本的必有字段。质量包与独立业务包的时间/人群不同则并列披露。最小连接测试不是完整数据报告，新增字段也不能只靠本地fixture通过；验收真实MCP及未登录/无站点权限拒绝路径。

记录每层日期、请求范围、脱敏结果、schema/版本、错误类别，不回显请求鉴权。连接测试只证明该次允许范围，不宣称能查看全部租户、全部原始字段或所有历史数据。

## 5. 固定窗口、分页与失败处理

从实际schema取得可用period/filters，首次响应后冻结返回的窗口和时区。后续复用原参数及nextCursor，不重算“今天”或手工拼cursor；校验推进、排序、范围、组数与事件总量，保留重复事件的multiplicity。返回契约未提供某项校验量时显式记录不能校验，不伪造计数。

- 本fork已记录cursor有效期30分钟、live尾端延迟5秒、历史90秒；重接新版本先核对。这些是版本事实，不是平台永久保证。
- 401：检查凭据来源/过期；403：检查site授权；缺工具：检查部署分支/版本/客户端重连，不用旧统计假替代。
- 409、cursor失效、总量变化：本次包标incomplete，从首请求重启整轮；不拼接旧页与新页。
- 超时、5xx、限流：保留失败和进度。纯读取可在同绑定下有限退避，默认最多重启一轮；再失败则停止并报告，不能无限循环或悄悄缩短窗口。
- 缩短窗口需说明新范围是另一份数据；日摘要不能相加伪造跨日独立会话。响应非预期JSON、代理页或业务错误不能因HTTP200算成功。
- 已接收完整性不等于事务快照：这是有界、append-only窗口证据；迟到写入和保留期仍有限制。

分析与问题卡使用 [真实数据与优化](data-review.md)。没有本次实测时，只能交付“配置/静态验证完成，连接待验”，不能记录 `connected=true`。
