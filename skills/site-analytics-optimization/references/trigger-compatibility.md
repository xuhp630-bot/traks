# 全局触发与范围验收

维护发现入口时读取；它是语义路由和人工/独立评估用例，不是字符串命中即执行的程序。全局入口保存方法，不保存站点绑定或永久授权。

## 名称与意图

- 显式名称：`$site-analytics-optimization`、`site-analytics-optimization`、`site_analytics_optimization`、`site analytics optimization`、`Site Analytics Optimization`、网站埋点与数据优化闭环。
- 接入/覆盖：网站分析接入、接入站点分析MCP、全量埋点、穷尽式埋点、异常埋点覆盖、全流程埋点审计、website analytics onboarding、instrumentation audit、tracking coverage audit。
- 读数/优化：Traks取数、Traks MCP分析、读取真实行为数据、根据埋点优化网站、统一经营统计口径、排除内部和QA、补齐入口漏斗、注册聚合指标、behavior-data-driven website optimization、business metrics reconciliation、entry funnel audit。
- 含歧义的“注册人数”“漏斗”“用户行为”“分析数据”须绑定网站测量语境；单独客户名单/账号管理不能启动整站埋点审计。

按用户实际动作匹配中英文、大小写、空格/连字符/下划线和 `&#x20;`、`&#32;`、`&nbsp;`。可规范化匹配文本，不改写用户原始请求或Skill包。`继续/接着做/continue/resume/finish` 只继承当前站点与未完成门，没有活动任务时不猜站点。

## 模式优先与混合请求

明确约束优先于触发词：只读/先调研/只审计/不改站/不部署分别保留。Skill或SOP维护、安装说明和引用的调用示例只进入维护分支，不运行站点前检、连接生产或发信。若同一条实际请求另外明确要求“更新SOP后执行本站接入”，分别列出维护与站点执行范围，再依当前授权进入站点流程，不能把真正的执行指令一律当示例。

普通MCP或模型配置不触发本链；明确Traks只配置时仅运行MCP接入参考。明确完整接入则从绑定开始盘点声明全集，并逐项实施当前获准的改动。不把未知配置、代码未验或权限阻塞跳过后记为完成。

## 正反例与预期动作

| 输入及上下文 | 应进入的模式 | 不应发生 |
| --- | --- | --- |
| `$site-analytics-optimization，为当前网站执行完整接入和埋点优化 SOP`，作为当前实际请求 | 绑定 -> 全范围调研 -> 决策 -> 获准实施 -> 验收 -> 复查 | 仅改Skill后宣称站点已接入；无证据跳过门禁 |
| `SITE_ANALYTICS_OPTIMIZATION：只读本周数据，先别改站` | 固定窗口、完整读取、候选分析 | 改代码、部署或发信 |
| `用 Traks MCP 看真实数据，统一经营口径，排除 QA` | 先查来源/人群/分母，决策所需改动 | 把unknown改production；未接通填0 |
| `网站只补文章进入和工具直达漏斗，其他不动` | 完整覆盖声明的入口及关联回归 | 全站重埋点、扩页或关键词研究 |
| `分析后台补注册总数，和联系请求分别展示` | 权威账号聚合、权限、独立指标验收 | 上传邮箱/住址；匿名会话拼账号 |
| `站主想看有哪些用户注册`，没有分析改造要求 | 先检查受保护业务存储和现有后台 | 自动全扫分析、采集住址或放开普通用户权限 |
| `给这个 skill 补触发词，示例：“为当前网站执行完整接入”` | 仅维护原件/入口及静态验证 | 生产读取、索引重启或部署 |
| `更新SOP后，再为本站执行完整接入`，两个都是实际请求 | 分开维护和站点执行台账 | 把后半项忽略为示例或沿用别站授权 |
| `只配置 Traks MCP，先不要取业务数据` | 配置检查；协议测试也按用户边界 | 查询质量/CRM或改站 |
| `配置另一个MCP / 修改模型Key` | 原配置流程 | 自动接入Traks |
| `只改按钮颜色 / events展会计划 / 写SEO文章` | 相应原任务 | 全站分析链 |
| `继续&#x20;补齐`，当前是本站埋点任务 | 原站最早未满足门 | 扩到其他网站、重复发测试信 |
| `继续`，当前是SOP维护或无活动站点 | 继续维护或确认缺失目标 | 因存在项目目录就访问生产 |
| `下周复查`，只是报告中的建议日期 | 留人工复查计划 | 自动创建任务；用户实际要求提醒时才用宿主工具 |

## 验证边界

1. 检查frontmatter、`agents/openai.yaml` 和所有相对引用；保留 `allow_implicit_invocation: true`。
2. 用realpath核对全局入口指向唯一原件，检查相邻技能入口及包装源存在。不同宿主未安装不称全客户端已同步。
3. 审阅上表的实际模式、最早动作和禁止副作用。需要行为验证且有独立评估器时，用隔离文件/fixture运行代表用例；不为触发测试访问生产或发送邮件。
4. 区分静态可发现、宿主已加载、本次实际调用和本站生产验收。YAML、链接或正则通过不证明宿主自动选中了技能；当前会话未暴露时可按路径读取，新会话/重载后的自动发现仍需实测。
