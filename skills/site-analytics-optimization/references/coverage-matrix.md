# 声明范围内的全流程覆盖矩阵

先从实际路由、业务入口、处理器、API、异步回调和错误分支建立全集，再分层验证。站点没有的业务标N/A，不为了补事件数添加无用功能。

## 盘点表

每一行记录：`flow_id / route / locale / device / entry / handler_path:symbol / state / event / producer / properties / privacy / dedupe / test / observed / status / evidence / owner`。

状态枚举：`verified`（测试或真实回执注明来源）、`implemented_unverified`、`partial`、`excluded`、`not_applicable`、`unknown`。声明分母时保留所有行；“已实现/适用项”与“生产已观察/适用项”分别报告，不把无生产事件当失败，不删除未知项提高覆盖率。

## 按用户任务遍历

| 层次               | 检查的入口与动作                                        | 不成功/异常                                                 | 结果与恢复                                                 |
| ------------------ | ------------------------------------------------------- | ----------------------------------------------------------- | ---------------------------------------------------------- |
| 进入与页面生命周期 | 首次进入、SPA切换、返回、刷新、可见/隐藏                | 404、路由边界、hydration、加载前失败、页面退出上报失败      | 页面就绪、关联新page visit；不可见不等于放弃               |
| 阅读与内容参与     | 预设滚动深度、关键模块可见、内容展开、外链选择          | 观察器不可用、布局变化、外链失效、窗口打开被阻止           | 阈值一次去重；不记录逐像素轨迹，不把可见/时长当阅读证明    |

| 表单与输入         | 开始、有效修改、提交、重置                              | native/custom校验、禁用按钮、跨字段错误、空结果             | 拒绝后纠正、再次提交；普通订阅/搜索不污染工具漏斗          |

## 分支交叉检查

对每个适用关键处理器验证：正常、空输入、边界输入、校验拒绝、业务前提未满足、网络失败、HTTP错误、内容无效、取消、超时、重复、并发、重试成功、重试仍失败、页面切换、窗口外返回。

设备/语言按网站实际支持集全覆盖关键路径，不随机抽样冒充完整；其余声明风险驱动范围。QA必须隔离，支付/邮件/删除等有真实副作用的路径使用sandbox或安全fixture，绝不为了埋点触发真实扣费。

## 每事件最小契约

- 触发：真实处理器状态，不是推测的按钮文本；“attempt/failed/blocked/invalid/cancelled/success”语义明确。
- 白名单属性：短期会话/页访问/版本、路由模板、业务类型、枚举原因、必要状态码、语言/设备；先确认平台上限和优先键保护。
- 禁止原文：输入、表单内容、邮箱、密码、搜索词、完整URL query、堆栈、响应体、授权头、Cookie、长期可关联身份。
- 去重：计数单位、重复窗口、生命周期和上限；UI重渲染或检查validity不能自行生成业务失败。
- 验证：触发动作、期望数量/字段、不应出现字段、接受端证据、无成功伪报、私密路由与隐私退出。

错误使用稳定错误码、类别、路由模板和安全来源标识，不上传原始message/stack/URL。覆盖同步异常、未处理rejection、框架边界、资源失败和业务API的网络/HTTP/语义失败；第三方cross-origin、tracker加载前/退出时和离线丢报列盲区，不承诺捕获全部异常。LCP/INP/CLS等性能信号保留浏览器支持、采样和单位，未观测不填0。

重试队列有上限、退避和独立错误预算，遥测失败不递归产生自身事件或阻塞核心任务。可选WebMCP/第三方包装遇到只读属性、抛错getter或冻结定义时安全跳过该增强，保留原调用返回/异常与原生pageview、自定义埋点正常初始化；不为“全量”强改第三方对象。

## 数据接收与读取验收

测试超出平台一页/Top-N的会话和事件数，保留重复次数；游标绑定站点/时间/时区/筛选，完整性校验失败禁止导出。迟到QA提升应排除整会话；未知不能回填production。会话标识缺失应统计并披露排除数量。

发布前核对客户端构建时配置与服务端运行时配置，尤其Vite等将环境值编译进bundle的项目。部署时有密钥不代表构建时有站点标识；检查最终client artifact的预期站点/采集端绑定，并用实际浏览器验证。源码通过、页面200、服务端绑定存在都不能代替该门禁。缺配置先阻止发布；已发布则按回滚点恢复，不向错误站点发QA事件。

QA标记必须通过真实CDN/Worker重定向、静态缓存和客户端导航完整保留。只用history.replaceState测试分类函数不能证明线上隔离；测试客户端应在转发前拒绝错站点或非QA的测试事件，而不是把失败请求改写成QA掩盖问题。发生测试误标时保存污染窗口/版本，取得授权后核对相关会话；不静默删除或当成真实用户行为。

不只检查“响应200”：验证body和业务语义。真实网络接收与历史存储分别验证；未知原因不能凭分类猜成CORS、DNS、广告拦截或用户意图。

页面健康和真实埋点分开验收：前者可用现有Playwright网络隔离第三方分析，但不能屏蔽本站pageerror或业务失败；有SRI的脚本不可随意替换响应造成完整性假失败。后者必须走获准QA接收及持久读回，不把mock、合成fixture、脚本存在或HTTP200记成真实收数。

经营视图变更增加同口径/刷新/新旧切换验收，入口变更增加完整文章/直达/目录及无法关联场景，注册变更增加快照/窗口/PII/权限场景。三者的契约分别见 [真实数据与优化](data-review.md) 和 [CRM证据链](crm-followup.md)；不只测新默认页而漏掉原有延迟加载视图。
