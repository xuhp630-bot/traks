# 渠道、有效线索、授权跟进与留存证据链

本分支是可选业务适配，不要求每个网站新建CRM。优先复用已授权CRM、邮件服务、签名Webhook和数据库；不同站点重新定义有效任务和人群。只读MCP不发送邮件、不创建联系人许可、不替代客户名单。

## 业务语义与计数

| 层次 | 最低可验证证据 | 不能宣称 |
| --- | --- | --- |
| 获客渠道 | 安全UTM/referrer与首次已观察入口 | 访问量就是有效线索；没有join却声称线索来自某渠道 |
| 请求受理 | 服务端持久请求ID、幂等结果 | 浏览器点击/表单success等于独立服务端记录 |
| 有效线索 | 已定义可行动标准与有来源的确认 | 自动把全部提交计作客户或成交 |
| 联系许可 | 本次请求回复与营销订阅分开记录，可撤回 | 一次联系或测试授权等于长期营销授权 |
| 跟进受理 | 原子发送claim、稳定幂等键、provider邮件ID | accepted等于送达 |
| 送达/失败 | 验签通过且持久保存的供应商回执 | delivered等于阅读；后续成功擦掉历史失败 |
| 入站候选 | 专用回复地址关联和声明From分类 | 匹配就是真人回复、自动回复已过滤 |
| 确认回复 | 站主核实或另一项已验收可信来源 | 元数据候选自动升级已确认 |
| 有效使用留存 | 合法、成熟且有价值的重复业务行为 | 邮件open/click、扫描器或页面访问等于客户留存 |

匿名行为、业务请求、发送尝试、入站邮件、账号留存分别保留分母。若没有合规且已验证的身份/归因关联，渠道行为与CRM聚合分别报告，`unlinked` 不是0转化，也不能用时间接近或设备特征拼身份。

## 注册聚合不是匿名转化

需要注册人数时先检查现有受保护账号后台与权威auth数据库；只读聚合优先复用既有接口，不为计数复制账号库或新增CRM。该fork可选 `registrations` 字段的语义是：

- 当前数据库账号快照：记录 `as_of`、数据源和排除规则。包括当前保留的站主、测试、封禁账号；已删除账号不计。不能称为真实客户数或终身累计注册。
- 窗口新增：当前仍在库且创建时间落入from包含/to不包含窗口的账号，不是完整历史注册事件。若需要含删除的历史统计，先检查已授权审计源，不能从快照倒推。
- 站主/其他账号、已验证/未验证、封禁是不同维度，不能跨维度求和。验证状态不证明真人；没有可靠测试账号标记时，其他账号不等于自然用户。
- 总账号存量不随浏览器production筛选变化；窗口/快照日期显式显示。若需要净业务账号数，另定义有证据的排除与未知，保留原全量口径。
- 注册、服务端联系请求、浏览器项目保存分别报数。缺字段、未接通、null、失败不得写0，匿名事件也不能证明数据库保存或账号创建成功。

分析桥只出白名单数值及覆盖说明，不出邮箱、住址、用户ID或账号明细。若用户另行请求站主名单功能，明细仅留在授权业务后台；“仅我可看”须服务端验证明确站主身份，不仅隐藏按钮或依赖可自行设置的role。普通新注册不得继承站主权限。验证未登录、普通用户、非本站凭据、站主各自的响应及缓存隔离；401/403是预期拒绝，不是运行故障，noindex不是鉴权。

注册聚合不需要新增住址或自动定位。另行提出这类功能时，单独评估目的、必要精度、用户告知/许可、拒绝路径、保留和删除；不能当作本SOP自动采集项。

## 实现与权限门

- 服务端持久请求ID；同ID同内容幂等、同ID不同内容拒绝。支持重复/并发、迟到QA、过期清理和用户撤回，旧客户端缺ID的去重盲区披露。
- 客户详情只在授权业务存储；站主管理端验证身份和角色、private/no-store/noindex。跟进需草稿预览、有效许可和发送确认，默认不启用营销；QA/internal/unknown不混入生产，也不绕过生产禁发规则。
- 发信使用稳定幂等键、原子claim与持久状态。退信/投诉/撤回/抑制发送前检查；`sending/uncertain` 先向供应商核对，不自动重发、不换键或新建同内容草稿“清错误”。服务端签名回执处理早到、重复、乱序，存储失败给供应商可重试失败响应，不返回伪成功。
- 验签用成熟SDK，保留签名时间窗、payload限制、事件/邮件ID幂等。匿名分析只出白名单数值及枚举，不带地址、主题、正文、附件、联系人/业务ID或原始payload。
- Traks业务桥按站点绑定精确HTTPS origin和独立只读token；拒绝未批准重定向及PII透传。工具的只读标注不代替服务端鉴权；不接受任意上游URL。
- 说明本地业务表、匿名分析、供应商、支持邮箱和备份的保留期差异；惰性清理不等于每日物理清除，不擅自新增cron或宣称删除全平台同步。

## Resend实操：发信与收信分开验收

只有实际选用Resend时使用本节；先核对当前账号、SDK和官方文档。

1. 检查已有Key的权限与生产secret是否配置，只显示“存在/缺失/权限范围”。sending-only Key对domains/webhooks报 `restricted_api_key` 不代表不能发信；不要自动扩权、换Key或重建Webhook。
2. 配置前展示实际目标、事件订阅增量、secret写入和迁移影响；只执行本轮获准动作。发送开关、业务持久化、送达回执、入站收信独立控制。
3. 真实邮件只发本次明确授权的测试邮箱与数量。使用独立QA请求/测试类型、固定幂等键、原子claim、持久状态；测试脚本不绕开生产禁止向QA跟进的规则。默认不自动重试，结果不确定先只读核对。
4. 依次核验：本地/指定发送路径供应商受理 → 真实生产handler签名回执 → QA数据读回 → 用户实际回复 → 入站关联。测试直调供应商不证明Worker内Key相同，亦不证明站主管理后台逐封生产路径验收。
5. 如账户已有可用managed receiving domain，可优先评估它避免改主域MX；不能猜域名或默认为所有账户可用。审阅入站表迁移后部署配置，再为既有Webhook增量添加 `email.received`，保留既有订阅与签名secret。
6. 不透明、不可猜的单封Reply-To别名关联本配置域、唯一目标、有效期内且尝试发送的邮件。未知/歧义/未发草稿不关联；sending/uncertain可留核查证据，未受理邮件不计候选指标。声明From不匹配单列，不能据此认证发件人。
7. 入站只保存供应商ID、内部关联、分类、发生/收到时间。正文在授权供应商后台人工核实；不自动抓邮箱/附件、回复客户或发营销。旧邮件无专用地址不回填。
8. 没有用户真实回复时记 `implemented/configured; live_inbound_pending`。后续“继续”仅核对原测试状态，不重复send；模拟Webhook不能代替真实入站。

## 本fork的只读字段

`get_crm_quality(siteId, from, to)` 读取最近90天内的显式UTC窗口，from包含、to不包含，不支持匿名漏斗filters。重新接站或升级后以实际工具schema与后端契约为准。

先读连接/发送开关/送达覆盖，再读业务计数及成熟留存；`not_connected`、错误、null不能填0。匿名质量包中的 `growthCoverage.crmConnected=false` 表示该包没有业务join，不能据此否定独立CRM工具已连接。

`inboundEvidence` 必须保留：

- `coverage`：配置/观测范围，配置成功不等于真实入站已验收。
- `counts.candidateRequests`：请求去重；`matchedMessages` / `senderMismatchMessages`：入站provider邮件去重，不能相加当客户数。
- `identityVerified=false`、`autoReplyFiltering=not_available_metadata_only`：别名+声明From不能证明真人，也无法从这份元数据过滤自动回复。
- `automaticCustomerReplies=null`：不以候选数量覆盖；人工确认回复保留人工来源。

候选计数按同一请求创建窗口及回执发生截止时间，未配置为null。漏掉有效期前、旧地址、未知关联、第三方过滤等盲区要保留，不能称为完整邮箱同步。

## 留存与业务复查

每站声明账号/请求/访客中的哪一种人群、有效起始行为、有效回访行为、合法关联标识、时区日边界、成熟期、排除规则和保留期。已有示例只测已验证账号成功保存项目的UTC成熟D1/D7/D30，不是全站用户留存，新站不能照抄该事件或分母。

排除owner及规定的QA/internal/unknown人群，尊重DNT/GPC和私密页面；分母0时rate=null，未成熟不入分母。保留期内首次观测不等于终身首次，best-effort写入可能丢失。按 [真实数据与优化](data-review.md) 保存同窗口前后证据，不用QA测试证明增长或因果改善。
