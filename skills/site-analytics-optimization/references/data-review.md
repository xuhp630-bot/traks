# 真实数据交付与优化复查

## 读取前

绑定站点、property/siteId、授权角色、数据源、时区、UTC起止、筛选、版本与发布日。优先已有官方API/项目客户端或用户导出；登录失效请用户在专用浏览器登录，不复制Cookie或绕过权限。

默认先分析production标签，另列QA/internal/unknown。生产标签不保证真人或自然搜索来源；历史未标记数据不能自动重分类。只看保留的已授权数据，不回收被明确排除的敏感字段。

## 经营口径与分母

为每项指标登记 `source / unit / numerator / denominator / population / window / timezone / filters / exclusions / version / completeness / null_reason`。总量类指标无比率分母则注明N/A，不硬算成百分比。

- 默认经营PV、自定义事件、目标与趋势取自同一选定production会话集合，不把原始Top-N或混合会话数当转化分母。原始视图单独标记，QA/internal排除，unknown作为数据质量事实单列。
- 会话目标率使用“观察到目标的去重会话数 / 同范围合格会话数”；事件次数、操作数不能除以会话后标为用户转化率。严格漏斗的阶段分母按冻结契约展示，不能与非顺序目标混称完成率。
- 独立业务聚合以服务端事实为准，窗口/人群不随匿名filters静默变化。账号存量、窗口新增、联系请求、浏览器保存分别展示；没有join时不求注册或线索的匿名会话转化率。
- 分母为0时rate=null；完整读取的真实计数0、数据缺失、未接通、读取失败必须区分。一个来源失败不得清空另一个已成功来源，也不能保留旧值却去掉其日期/错误提示。
- 改看板默认口径时验证新旧视图来回切换、延迟加载、时间切换、全局刷新含CRM/账号数据、错误/重试/空态和桌面/手机。UI、导出和实际MCP在相同绑定与窗口下对账。

## 入口与严格漏斗

从真实用户任务建立入口集合；内容站常见文章 -> 工具、搜索或外部直达工具、目录 -> 工具，但新站应按自己的路由定义。工具直达不自动等于搜索来源，搜索须有已观测来源证据。入口人群可重叠，不能把分组相加当独立总访客。

每条漏斗分别定义入口、有效到达/ready、有效输入、成功结果和结果使用；未观测到前一步不能靠后续成功回填。目标事件只是发生过目标，不证明完整入口链路完成。

页内关联要求同会话、pageId、规范路径、版本、语言、设备及匹配的已知工具；跨页导航必须有显式目标/工具映射和可验证的前后page visit，不能要求两页使用同一pageId，也不能仅按时间最近拼接。接收时间需严格递增；重复/分组multiplicity、并发、同时间戳、缺标识、跨版本或歧义保持无法关联。若只有聚合而缺逐条证据，不能还原未记录的顺序。

修正文章入口时，从文章意图、可见CTA、目标工具实际能力、底部推荐和关键词owner一起核对。优先显式语义映射；短字符串偶然包含不能决定推荐。测试完整受影响文章/工具与语言集合、首按钮及推荐、成功到达与返回，不为了修链接重写无关正文或新建同意图页面。

Traks MCP连接、schema与分页错误处置见 [MCP安全接入](mcp-onboarding.md)；CRM需 [独立业务证据链](crm-followup.md)。原始保留证据只在受限范围读取，分享给站主的需求包默认脱敏聚合，不把“所有埋点”理解为无限原始日志或全租户权限。

## Unknown诊断先于流失推断

在支持本fork分类的版本中，检查 `population.wholeCohortUnknownClassification` 与选中人群分别代表的范围，不能把全队列unknown数除以筛选后production分母。字段不存在先核对版本/契约，不填0。

- `pageview_only_unknown`：只有原生pageview且无上下文，不能判断真人/机器人，也不能推断未开始输入就是放弃。
- `legacy_custom_unknown`：旧自定义事件无版本；结合发布日核对是否历史数据，不默认为当前缺陷。
- `missing_context_unknown`：有版本但缺分类上下文；排查producer、构建配置、导航/重定向和属性限额，不应被后到legacy事件覆盖。

分类优先级 `QA > internal > labelled production > unknown`；迟到QA按整个已观察会话排除，dimension filters选会话后不能隐藏其其他页面的QA证据。显式QA标记、内部登录/可信测试配置与自动化信号结合使用，但不存在保证识别全部测试/机器人的自动方法；无可靠上下文保持unknown，不用UA猜真人或为了增加样本回填production。

`production=0` 或样本/成熟分母不足时，交付数据健康、接收状态、未知根因与补证需求，不输出用户流失率/优化有效结论。修复新埋点不会恢复从未采集的历史上下文；新版本单独观察，旧数据保留原分类。

## 完整性

读取所有分页并验证游标推进、排序、范围和总量。失败/取消/过期/总量变化必须重启或保留为incomplete，不能把部分包当完整。客户端列表分页不是导出上限。明确“选定观测窗口的会话摘要”与“完整生命周期/原始轨迹”的差别。

优先完整昨天或支持的固定时间范围。滚动7d可能包含当前未结束的一天，不等于7个完整自然日；“扫描完整”也不等于“时间窗已结束”。导出UTC边界并在匹配时间读取对照；若工具无法表达所需范围，记录限制而不是修改含义。合并多日摘要不能直接相加成独立会话，跨日去重需真实关联证据。

## 分析包

保留：schema版本、生成时间、站点、窗口、来源、流量、筛选描述、扫描完整性、所选会话、无标识/未知/受限数量、漏斗、操作、行为与问题聚合。

不默认分享原始会话/page/operation IDs、用户输入、搜索原文、报错原文、Cookie、令牌、本机手工状态。筛选值省略时说明比较前必须回后台核对；包里不带值就不能假装可完全自动重放。包完整但数据源盲区存在，两者并列披露。

## 需求候选格式

`事实 + 范围/分母 + 原因假设 + 反证 + 未知证据 + 复现步骤 + 优先级及理由 + 具体改动 + QA验收 + 主指标 + 防止误判的指标 + 负责人/需求链接 + 基线文件 + 发布身份 + 复查时间`。

优先修复可复现阻断、伪成功、隐私泄漏和测量失真。业务阻塞先核是否符合产品规则；不能删除权限或限额只为了减少错误数。零结果只能提示工具发现问题，无原文时不能推导用户搜索了什么或直接决定新增页面。

次数、会话数、独立用户、操作数和请求数不是同一分母。分组可能重叠，不求和冒充全站独立用户。按页面、语言、设备、版本分层，失败后成功不抹掉失败；未见返回可能来自窗口、离开、丢报或仍在处理，不等于永久流失。

推广链接使用非个人UTM短标签，比较渠道带来的有效操作/已确认业务证据，而非只看PV。没有匿名→CRM关联时明确两份数据尚未联通，不能按同一时段拼接出“渠道有效线索率”。优先输出有事实支撑的漏斗停滞、失败页面、输入未完成、复制/导出失败与高流量低有效操作候选；原生打印无法确认完成时列观测盲区，不凭缺success认定打印失败。

## 改动后

保存前后版本与埋点口径对应关系。QA验证成功/异常/阻塞/取消/重试和隐私后，经当前授权上线。当天是功能及接收验收；后续相同星期构成、设备语言、渠道/流量、页面、时区和筛选的完整窗口才用于业务观察。

通常从7天窗口开始；发布当日不是完整自然日时，以所选时区的次日00:00为起点，满7个自然日后的次日读取，并记录实际UTC边界。低流量延长14/28天，仍可能没有结论。阈值只是显示/决策纪律，不是显著性保证；非随机前后对照不证明因果。成功、失败、取消、未知、无法关联和限额一起看，防止因为测量变化形成虚假改善。

## 后续监控

用户要求持续跟踪时用可用的宿主定时工具，优先更新匹配任务。保存精确站点/仓库/读取方法、频率、允许动作、证据存放点、通知条件与退出条件。默认只读；通知仅用于新出现可行动问题、数据质量显著改变、验收完成/失败或必要用户操作。没有变化保持安静，访问失败不填0，不自动改站、提交需求或部署。

没有配置定时工具就只交付日期，不声称自动监控已启动。自动化创建成功也不代表数据已读取或未来一定能登录。
