# 网站埋点到优化闭环

先理解需求，再调研，再决策，再执行。目标不是多发事件，而是让每个重要用户任务的成功、失败和未知状态都有可解释证据。

## 选择本次范围

- **接入/补齐**：读 [覆盖矩阵](references/coverage-matrix.md)，从真实路由和业务处理器盘点，不从示例事件名推断业务。
- **读数/复查**：读 [真实数据与优化](references/data-review.md)，优先用现有授权API或用户导出，不重新造采集平台。
- **Traks接入**：再读 [Traks适配注意事项](references/traks-adapter.md)。其他平台保留其原有事件、隐私与会话约定。
- **只整理SOP**：输出方法与待验项目，不部署、不读取生产数据、不自动创建监控。
- “继续”只继承当前网站和未完成步骤，不能启动其他网站全扫。

## 1. 理解并绑定

明确实际repo/worktree、生产origin、分析站点ID/属性、业务目标、主要流程、语言/设备、授权读写边界和发布目标。多站点逐站绑定，不继承上个站的账号/漏斗/关键词/数据。

优先读取项目规则、现有analytics适配器、事件目录、测试、发布与隐私回执。遵循宿主的代码图谱生命周期和SEO前检，但不把埋点任务变成新页面研究。记录允许的采集基础：同意管理、DNT/GPC、私密路线、业务敏感字段、保留期与访问角色；无cookie不等于无需法律或同意评估。

## 2. 调研全部声明范围

冻结路由/流程/状态/设备语言的覆盖全集，逐项连接到源文件与处理器；按矩阵填写已覆盖、部分覆盖、不适用、明确排除、未知。第三方、登录后、服务端、离线和加载前故障不能因看不见就算通过。

已有成熟SDK、框架错误边界、表单校验、Web Vitals和事件队列优先复用；仅在需求确实缺能力时扩展。不要以通用click监听替代业务结果，也不要无差别抓fetch、DOM文本、输入或请求体。

## 3. 决策并形成事件契约

每个事件说明它回答的业务问题、真实触发点、属性白名单、数据源、计数单位、隐私/限额、验证方法和版本。采用已有命名约定；缺结果不能发success，用户取消/校验/权限或配额阻塞与系统异常分开。

冻结QA/internal/production/unknown分类和去重规则。版本、同会话/同页访问、严格时序不足时标为未知或无法关联；需要精确并发关联再引入短期operation ID，不从巧合的时间戳猜测。成功不抹掉失败，点击下载不证明文件保存，创建结账链接不证明付款。

先声明准备改哪些代码、UI、目录与验证；不把数据候选自动批准为产品改动。提交/推送/部署、付费、DNS、密钥、迁移与定时任务沿用本次明确授权，不能由安装Skill获得永久权限。

## 4. 执行与验收

实现业务开始/完成/拒绝/错误/恢复的最小有用信号，更新目录和相邻现有测试。隐私退出应在采集前生效；错误分类和元数据在接收/API边界也要白名单化。保留未知，避免原文泄漏和自动重试造成事件递归。

用隔离合成数据验证矩阵，包含多页导出、重复、乱序、跨页面/版本、迟到QA、限额、取消与失败读取。UI要展示范围、完整性和盲区，曲线与旧统计口径不混入新漏斗。小屏、键盘、加载/错误/空态一起验收。

发布时保存前版本/回滚点，检查实际目标与资源、秘密不入日志，核对最终artifact。部署后用QA标记验证真实接收与当前/历史读数，单独记录生产验证是否成功；不把本地SQLite或mock当成云端SQL方言验证。

## 5. 真实数据 → 优化 → 复查

完整读取已授权窗口，保存脱敏聚合包和范围清单，再生成事实/假设/反证/待补证据/优先级/具体改动/验收/观察指标的需求候选。样本、分母或观测覆盖不足时优先补测量，不判定流失或因果。

经确认只执行一个可验证假设，记录基线、负责人、提交/Worker版本、QA结果和复查时间。按匹配的完整窗口再次取数，区分功能修复与业务改善。用户需要后续监控时才用宿主自动化工具，先检查既有任务避免重复；没有可行动变化保持安静，登录/权限失效只提示必要操作，不绕过授权。

## 必交回执

1. 精确网站绑定与业务目标；声明覆盖全集和分母。
2. 覆盖矩阵、事件契约/目录与新增/修改/排除项。
3. 真实测试及发布身份，盲区/阻塞；图谱状态与范围限制。
4. 脱敏数据包、采集时间/窗口/来源/完整性、QA与unknown分离。
5. 需求候选、基线、上线和复查计划；自动化创建状态如实注明。

“穷尽式”只指完成已声明矩阵，不保证所有浏览器、网络、第三方或未来代码都被采集。报告必须列出未覆盖、丢失、限额、无权限和未验证部分。
