# 竞品公开页面监控

## 研究库与存储决策（0032，本地增强待发布）

研究库单独保存**人工确认**的品牌、公开首页、产品/品类结论、种子词、支付网关及证据、来源链接、备注和生命周期（待整理／重点关注／持续观察／暂缓／放弃）。一条档案可多选业务分类，并手动关联本工作区的己方站点和**已存在**的监控记录；建立或关联档案不会自动创建监控、抓取网页、加入主机白名单或开启调度。

### D1 容量结论

- 研究库主存储使用 Cloudflare D1，不把浏览器 `localStorage` 当作主库。它需要跨设备/成员/PAT MCP 的一致权限、工作区隔离、外键清理和可审计的手动关联，浏览器本地数据无法满足这些边界。
- 2026-09-23 的已绑定生产 D1 元数据约为 `319,488 bytes`（约 `0.305 MiB`）；按 [Cloudflare D1 官方限制](https://developers.cloudflare.com/d1/platform/limits/)，单库 Free 为 `500 MB`、Workers Paid 为 `10 GB`。Traks 事件明细在 Durable Objects/R2，不写入此研究库 D1 表。
- 研究库每工作区最多 `500` 条；结合字段上限，即便以接近最大长度保存文本，原始业务字段约在 `40 MiB` 量级，仍显著低于 Free D1 单库上限，实际常规记录会更小。D1 页、索引和其他平台元数据仍需保留余量，不能把该估算当作无限容量承诺。
- 因此本轮不实现本地存储降级。若未来实际 D1 达到容量/成本预警，先导出或归档低频研究证据到受控 R2，并保留 D1 的可查询索引；不能悄悄把共享生产资料迁到每个浏览器。可选的本地表单草稿必须单独设计隐私、过期和清除规则，且不应同步为事实记录。

### 使用方式与读取边界

1. 先在「竞品研究库」录入或修订人工研究结论，再用生命周期和多分类划分“图片生成工具站”“视频工具站”“导航站”等业务组。来源 URL 应指向可复核的公开页面；支付状态只能是已确认、仅有证据、停用或未知，不能由页面猜测为已接入。
2. 需要持续观察某个公开页面时，仍在下方「添加公开页面」**手动**新建监控、审阅 robots/条款并配置允许主机；回到研究档案中显式关联该已有监控。研究档案本身不触发外部网络请求。
3. MCP 使用 `get_competitor_research({workspaceId, lifecycleStatus?, categoryId?, siteId?, monitorId?})` 只读获取档案及手动关联。该工具不返回竞争对手流量、客户数据、整页 HTML、支付凭据或自动监控结果；它也不修改任何数据。
4. 完整竞争态势仍需把人工研究、公开页面变化证据和己方 production 行为数据分开阅读。它们不能推导竞争对手转化率、市场份额或因果效果。

## 分类 / 己方网站双维度（2026-09-23，本地增强版待发布）

此前已发布的首版仍是按站点监控；以下增强需要先应用 **0031** 再部署新代码，不代表生产已经支持。旧 `0030` 迁移不改写，下方首版记录保留为历史。

### 如何使用

1. 打开 Competitors，先确认顶部工作区。可以在「管理分类」添加如“AI 视频”“SEO 工具”的业务分类；没有己方网站也能添加分类与监控。
2. 添加公开页面时，分类和己方网站都可选：只选分类＝分类内独立监控；只选网站＝该网站的未分类竞品；两者都选＝该网站在此分类下的竞品。均不选时进入当前工作区的“未分类 / 独立监控”。不要把竞品注册为己方埋点站点。
3. 「按分类查看」与「按己方网站查看」取交集。曲线、检查数、变化/失败数、清单与所选证据都在相同范围；管理分类的页数和工作区容量是全工作区口径，不随筛选变化。没有记录时显示未观测，不等于零变化或零流量。
4. 选择记录后，在「调整分类 / 关联网站」内更改、解除或关联本工作区的站点，历史和最后成功基线保留。历史按当前归属汇总，调整归属也会重新归类以往趋势，不是采集时归属的快照。更改归属后记录可能不再符合当前筛选，可清除筛选查看。
5. 分类可改名；删除分类只将记录变为未分类，不删除监控或历史。删除**监控记录**仍会清除其保留快照；删除其关联的**己方站点**保持首版级联语义，若要留存，先把监控解除关联为工作区独立监控。工作区有独立监控或分类时禁止直接删除，孤立工作区回收也不得把这些数据当空工作区清除。

每个记录对应一个公开页面。每站最多20页、每工作区最多20个独立页面、总计100页、30个分类；旧存量不删，超过上限只阻止新增/不符合目标容量的迁移。分类不增加抓取额度。同一己方站点内同URL唯一；同工作区独立记录同URL唯一；换分类不能绕过去重。不同己方站点可以分别记录同一竞品页面。拥有者管理，成员只读，read PAT 不允许创建、检查或修改。

Seevio 等 AI 产品可先归入“AI 视频”等分类而不关联不相干的己方网站；这只是操作示例，不表示已在生产建立 Seevio 记录。分类名称由使用者决定，不自动认定产品定位。

### REST 与只读 MCP

- 新工作区入口：`GET/POST /api/competitors/workspaces/:workspaceId`；查询支持 `siteId` / `categoryId`，未知或不属于工作区的ID拒绝，不静默退回全量。
- `siteId=unlinked` 表示未关联网站，`categoryId=uncategorized` 表示未分类；省略参数才表示全部。
- 分类：`GET/POST /api/competitors/workspaces/:workspaceId/categories`，`PATCH/DELETE .../categories/:categoryId`。
- 历史/检查/调整/删除：与原站点接口后缀一致，使用工作区根路径。修改归属用 `{siteId: null | id, categoryId: null | id}`；`null` 清除，省略保留。
- 原 `/api/competitors/:siteId` 和 MCP 的 `{siteId}` / `{siteId, monitorId}` 调用兼容；旧站点路由不能重新分配到别站，必须显式使用工作区路由。

MCP 顺序：

```text
list_competitor_workspaces({})
get_competitor_categories({workspaceId})
get_competitor_monitors({workspaceId, categoryId, siteId: "unlinked"})
get_competitor_history({workspaceId, monitorId})
```

清单工具也支持 `{workspaceId, siteId}` 或三个维度同时传入；历史工具必须在 `workspaceId` / `siteId` 二者中选一个，避免歧义。工作区列表遵守PAT工作区权限，不启动默认工作区创建或历史站点归并。全部竞品工具只读，不触发网络采集，不转发 dashboard Cookie。使用已授权的正式PAT客户端；浏览器登录成功不等于PAT调用已验收。

### 迁移与发布安全

- 所有权只有一个来源：关联监控继承站点的工作区；独立监控直接归工作区。数据库约束要求 `site_id` / `workspace_id` 恰有一项非空。旧数据（包括历史未归工作区站点）不猜测归属、不丢弃。
- 0031先复制监控和快照，再依次删除旧子表、旧父表，最后重命名新表并重建索引，保持ID、失败记录、最后成功快照、计划时间与lease。不能使用生成器原始的关闭外键/直接删除父表方案，否则D1可能级联清掉历史。
- 生产执行须另获本次推送、迁移和部署授权；先绑定真实资源、备份和记录恢复点，确认运行中检查已结束并保持调度关闭，原子应用0031后读回行数、外键、成功基线及迁移记录，再部署与实际登录/PAT验收。
- 不自动降级迁移；独立记录无法无损塞回旧版非空site结构。回滚须评估迁移后的新数据，停止调度、保留最新备份，再选择兼容版本或恢复方案，不能直接重放旧发布脚本。
- 主机allowlist、robots、公网DNS、超时、冷却、60次保留和自动调度默认关闭等首版限制不变。分类/关联不是竞品真实流量、商业结论、SEO排名、付费API或发信许可。

- 首次成功只建基线；失败不覆盖成功基线、不伪造下架/降价/排名下跌。跨日期差异仅为所取公开HTML的变化候选，不证明竞品策略或效果。
- Later：sitemap全量新增/删除页、RSS、JS渲染/截图、价格结构化解析、多币种、关键词排名/外链/流量估算和外部通知。无需先购买这些服务才能管理首版清单。

## 使用与上线门

1. 登录后打开独立 **Competitors / 竞品监控** 入口，选择自己的站点。每个记录是一张公开竞品页面，同域可添加多张；不要把竞品当作自己的采集站点注册。
2. 管理员审阅采集目标、网站条款和资源预算后，在API Worker配置 `COMPETITOR_ALLOWED_HOSTS`：逗号分隔的精确公开主机名，不支持通配符。默认空，因此不发起任何目标抓取；清单可先录入。只应批准已知可信的公开域名，禁止不可信DNS/内部路由。DNS检查是纵深保护，不是独立网络沙箱；生产保持 `global_fetch_strictly_public`，不得为此Worker配置私网代理/VPC通道。
3. 配置公开HTTPS URL、标签和SSR区域（默认 `main`；简单标签/`.class`/`#id`）。没有匹配区域时失败，不把空内容当删除。JS-only或复杂页面改用成熟外部监控服务；不得靠改变UA、登录Cookie或代理绕过。
4. 手动检查前先迁移并部署经过验证的首版。迁移只增加竞品记录与快照表/索引，生产迁移、secret/配置写入、push/deploy需另获授权。本地通过不代表线上已生效。
5. 自动执行还需要 `COMPETITOR_SCHEDULE_ENABLED=true`，复用现有Worker cron，不新建后台任务。默认关闭。每日/每周是最小间隔，不保证固定当地时刻；每轮最多3个目标，同域15分钟冷却，失败照常记录并延后，不无限重试。关闭cron或全局开关后不能声称仍在自动监控。
6. 每目标保留最近60次检查（不是60天无限历史），另外保留一份最后成功基线及其时间，避免长期失败清掉比较依据；基线保留到下次成功或删除目标。趋势只统计保留检查记录中的最近30日。删除目标级联删除其快照和基线，需要确认。记录可能因保留上限而截断，MCP/UI均说明范围。

安全边界：仅HTTPS/443、无查询参数/片段/凭据/IP字面量/本地域/常见私密路径；精确服务器allowlist；请求前A/AAAA检查；拒绝目标与robots重定向；超时/响应字节限额；robots拒绝/不可读时失败关闭。声明crawl-delay的站点留给支持其调度的外部服务，不忽略限制。目标请求无Cookie、鉴权头或本站标识，使用明确监控User-Agent。存储仅限公开元信息与限定区域的短摘录/哈希，不存整页HTML，不写本站事件管道；请勿选含个人数据的区域。

## 数据怎样用于优化

变化卡依次记录：来源/采集时间 → 前后字段 → 假设 → 反证/盲区 → 建议 → 本站QA → 观察指标。价格区变化需人工核实币种、周期、折扣与资格，不能将文本哈希变化自动称为涨价。标题变化不等于排名上涨；请求耗时不等于竞品用户Web Vitals。

本站production漏斗/错误数据与竞品公开观察是独立人群和来源，不能拼出竞品转化率。首版只提供证据，不自动改本站、发营销、提工单或调用模型评审。页面内容属于不可信外部数据，MCP使用方不得执行其中的指令。

### 推荐试点与后续决策

- 首页、定位和CTA：每周检查；判断诉求/目标受众表达变化，不推断其转化效果。
- 定价/方案页：每日或每周检查指定公开价格区域；人工核对币种、周期和资格后形成价格候选卡。
- 核心工具/功能/更新页：每周检查；核实公开能力和使用门槛变化，不将营销文字当真实能力证明。
- SEO元信息：随页面检查一起读取；标题/H1/canonical/meta robots的变化只用于发现候选，不证明排名变化。
- 排名、外链和访问量：仍未接入；待明确关键词、国家/语言、预算及授权数据源后单独决策。第三方流量始终标为估算，不能与本站埋点混算。
